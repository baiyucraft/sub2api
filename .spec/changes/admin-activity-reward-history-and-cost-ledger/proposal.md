# 用户领奖记录与活动奖励成本整合

## 问题

管理员的用户资金流水仅包含兑换及返利转入，无法追溯活动奖励或查看累计领奖。奖励已增加用户余额，但没有计入额外成本，导致今日、历史和累计成本缺项。

## 目标

- 在现有用户流水及用户操作菜单中查看四类活动领奖记录和累计金额。
- 活动奖励按入账金额等额记入领奖当日的额外成本，补齐全部历史。
- 新增成本与发奖事务原子提交，并保证查询、重试及补录幂等。

## 非目标

- 不改变活动资格、奖励区间、充值合计、用户扣费、邀请返利或用量日志。
- 不自行发布生产，不修改其他 active change 或历史 migration/profile。

## 成功标准

- SC-01：全部流水及活动筛选可稳定分页；累计领奖不受筛选分页影响。
- SC-02：每条已入账奖励恰有一条关联成本，日期和金额匹配；失败事务零副作用。
- SC-03：历史补录重复执行不重复记账，既有人工成本保持完整。
- SC-04：成本汇总、趋势、缓存和关联追溯完整，自动记录不可人工创建或冲正。
- SC-05：相关测试、前端质量门禁、VM PostgreSQL 集成证据和长期合同完成。

## 影响范围

- 管理员用户流水 API、用户列表与用量页复用弹窗。
- 活动发奖服务、额外成本服务/仓储及成本流水 UI。
- 新数据库迁移、发布合同、测试及 Wiki/fork 审计。

## 交付形态

single-change；四类奖励共用同一账本，可独立验证。原 daily-activity-rewards change 身份不变。

## 风险

- 混合来源同 ID 或同时间导致分页不稳定。
- 事务之外记账、历史日期错误、重试及发布切换遗漏导致成本失真。
- 历史数据回填必须保留金额、时间和人工流水，不再充值余额。
