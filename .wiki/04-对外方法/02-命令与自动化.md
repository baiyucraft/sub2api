- `make build`：后端和前端构建。
- `make test`：后端测试、前端 lint/typecheck 和关键 Vitest。
- `docker compose up -d`：按 Compose 启动服务。
- `go run ./cmd/server`：后端；支持 setup、migration plan/apply、version flags。
- `frontend/package.json`：dev、build、lint:check、typecheck、test:run、coverage。

迁移计划执行前必须确认 catalog/checksum 未漂移；CI、发布、备份恢复和生产健康核验属于受控流程。

Sub2API fork 的发布入口由 `sub2api-production-deploy` skill 统一管理：使用完整 commit SHA，按 profile 执行 `doctor`、`deploy-start`/`deploy-follow`、`status`、`wait` 和 `verify-result`。RackNerd 的发布命令、状态检查、镜像与恢复包传输固定经“DMIT SSH -> WireGuard 地址 1080 HTTP CONNECT -> RackNerd SSH”，使用 10 秒 keepalive，禁止回退到本机代理、旧 8888 或直连。RackNerd 的纯只读 `doctor` 综合探针可在 SSH 连接中断或 `exit_code=-1` 时有限重放；大文件下载与上传均使用 8 个可续传分片、最多 8 条并发连接，每个下载分片使用有界预取。发布写命令出现超时或非零退出时必须先读取结构化状态和 committed marker，不重复启动 runner。fork 差异审计由 `sub2api-fork-extension-audit` 只读执行，报告写入 `.tmp/fork-extension-audit/`。长期合同见[分叉扩展与兼容性](../03-模块指南/05-分叉扩展与兼容性.md)。
