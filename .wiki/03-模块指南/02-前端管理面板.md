# 前端管理面板

`frontend/src/main.ts` 创建 Vue/Pinia/i18n，读取注入配置和主题，安装 router 后等待 `router.isReady()` 再挂载 `#app`。`router` guard 处理认证、管理员权限、simple/backend mode、payment/risk-control gate、公共设置预取和动态 chunk 错误。

页面/组件 -> 领域 API client -> Axios interceptor -> 后端 route。Store 保存认证、公共设置、主题和运行时状态；错误通过统一通知处理，不泄露 Token 或上游凭据。管理面按账号、上游、渠道、计费、运维、备份、设置和审计组织。上游配置采用“上游看板 / 上游渠道 / 上游账号”三级入口；看板以配置为卡片粒度，支持 1h、24h、7d、15d、30d 窗口和右侧详情抽屉，旧 `/admin/upstream-configs`、`/admin/upstream-management` 地址不再注册。

## 用户充值商城

所有已登录用户（包括简单模式用户）以及管理员的个人功能菜单固定提供 `/recharge-store`“充值商城”入口，位置在“购买订阅”之后、“我的订单”之前，并与原生支付功能并存。该入口直接在独立 iframe 页面加载 `https://catfk.com/shop/baiyuapi`，不依赖 `payment_enabled`，也不复用自定义页面的 `buildEmbeddedUrl`。

商城属于不受信任的第三方页面，安全边界固定如下：

- iframe 和“在新窗口打开”按钮都使用未经改写的固定 URL；
- 不附加 Sub2API Token、用户 ID、`src_url`、`src_host`、主题或语言参数；
- iframe 使用 `referrerpolicy="no-referrer"`，但不设置会破坏第三方支付、脚本或弹窗流程的 sandbox；
- 应用 CSP 只放行精确来源 `https://catfk.com`，不得扩大为通配域名；
- 内嵌不可用时由页面明确提示用户改用新窗口，不在 Sub2API 内代理支付请求。
- 页面会在 iframe 加载期间提供状态反馈；加载较慢或失败时保留原始商城链接作为恢复路径。
- 移动端不尝试跨域改写商城内部布局，改为提高嵌入视口、避免宿主页面再次截断内容，并明确建议使用新窗口完成商品选择和支付。

该功能不新增设置、数据库字段或迁移；商城 URL、菜单名称和路由属于 fork 产品合同，变更时需要同步前端测试、CSP 测试和 fork extension catalog。
