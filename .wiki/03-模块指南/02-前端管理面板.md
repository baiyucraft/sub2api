## 上游配置看板

上游看板按 `upstream_config_id` 展示真实流量、主动探针、账号池和估算收益。列表卡片只承载窗口聚合；打开详情时必须请求详情接口，避免把列表快照当作完整详情。真实流量的收入/成本与主动探针样本分开统计，缺少币种或换算率时收益标记为不可用。无探针或无账号的配置仍应安全返回并展示数据不足，而不是因左连接 `NULL` 扫描失败。

看板跳转使用记录、渠道和账号时携带当前上游配置筛选；页面需处理异步刷新竞态、详情加载错误、键盘 Enter/Space、Escape 关闭和状态本地化。

卡片和详情按同一时间窗口分别展示渠道收入、上游消费、估算毛利和毛利率，金额与余额沿用同一记账显示单位并保留两位小数，百分比有独立标签。毛利允许负数，未知值显示不可用，合法零金额显示零；收入为零时毛利率不可用。收入表示用户实际扣费累计，不表示现金实收；消费保留请求发生时的成本和倍率快照，不按货币符号额外引入市场汇率或站内充值销售倍率。

## 上游渠道列表排序

上游渠道列表首次进入按配置 ID 正序排列；管理员可通过 ID、名称、Provider、余额、共享并发、调度状态、认证模式和最近同步列头切换正序或倒序。排序状态保存在浏览器本地；隐藏当前排序列时恢复 ID 正序。

所有排序必须由 `/admin/upstream-configs` 在筛选后、分页前执行，前端不得只重排当前页。余额排序仅使用 24 小时内的最新有效渠道余额快照，不可用余额始终置后；共享并发排序复用调度最终解析口径，并把明确无限制视为高于有限并发。未知排序字段回退 ID 正序，非 ID 排序以 ID 正序保证稳定分页。
# 前端管理面板

`frontend/src/main.ts` 创建 Vue/Pinia/i18n，读取注入配置和主题，安装 router 后等待 `router.isReady()` 再挂载 `#app`。`router` guard 处理认证、管理员权限、simple/backend mode、payment/risk-control gate、公共设置预取和动态 chunk 错误。

页面/组件 -> 领域 API client -> Axios interceptor -> 后端 route。Store 保存认证、公共设置、主题和运行时状态；错误通过统一通知处理，不泄露 Token 或上游凭据。管理面按账号、上游、渠道、计费、运维、备份、设置和审计组织。上游配置采用“上游看板 / 上游渠道 / 上游账号”三级入口；看板以配置为卡片粒度，支持 1h、24h、7d、15d、30d 窗口和右侧详情抽屉，旧 `/admin/upstream-configs`、`/admin/upstream-management` 地址不再注册。

## 上游账号列表刷新

上游账号页首次加载或切换分页、筛选、排序时加载对应查询结果；在相同查询条件下，手动刷新和自动刷新保留已有表格行，以账号 ID 合并最新列表快照，保持滚动和选择状态。列表快照变化判断包括缓存保护、TTFT、调度评分、健康和其它实际显示字段，不能只比较账号 `updated_at`，也不能把列表数据回填到未保存的完整编辑对象。

列表刷新绑定页面范围、分页、筛选和排序的请求版本；查询条件变化后，旧在途响应不得覆盖新结果。取消信号必须透传到 HTTP client。同一查询下的重复刷新合并在途工作，初次加载仍有骨架反馈；已有数据的手动刷新失败时保留行并提示错误，自动刷新失败时保留行且不弹通知。

今日统计、质量和支持的平台用量分别异步更新。探测设置读取不阻塞用量启动；手动刷新保留强制更新用量的含义，不能被已有五分钟客户端缓存或普通在途请求吞掉。普通用量请求正在执行时，合并重复强制刷新意图，在其完成后最多补一次强制批量刷新，避免通过取消再发形成重叠上游调用。

后端列表按当前页去重上游 Key，批量读取可信度及必要绑定和分布状态，复用本次请求的配置。旧七天探针汇总和独立分布模式保留各自窗口、排序、唯一绑定、协议及配置身份校验和数据不足原因。缓存保护只在本次列表请求内每组读取一次现有运行快照并按账号索引，不新增跨请求状态缓存，过期和不可用结果继续按原合同显示。

ETag 在列表组装后计算，304 主要减少响应传输和前端重绘；不能把它视为省略后端查询的证据。性能验证应固定账号数量和查询条件，分别记录查询次数、快照投影和页面更新行为；本地合成基准不表示线上刷新耗时。

## 使用记录缓存率

用户端与管理端使用记录复用 `UsageTable.vue`。Token 列在缓存读写数量旁显示轻量标签，只显示百分比（如 `98.60%`），不显示“缓存率”文字；Token 明细保留“缓存率”名称和百分比，不展示公式或计算依据。明细的中英文本使用 `usage.cacheRate`。

缓存率为 `cache_read_tokens / (input_tokens + cache_creation_tokens + cache_read_tokens) × 100%`，保留两位小数。输出 Token 不参与，缓存创建只使用聚合字段，不重复累加 5m/1h 分项；缺失、非有限或负数按 0 处理。有提示词但未命中缓存显示 `0.00%`，提示词总量为 0 显示 `—`；按图片计费的记录不显示 Token 缓存率。此指标依据使用记录中的 Token 分桶，包含强制缓存计费重分类的结果，不改写原始计费或新增接口字段。

回归入口：`frontend/src/components/admin/usage/__tests__/UsageTable.spec.ts`，覆盖截图样例、无命中、全命中、仅缓存创建、零分母、异常历史计数及图片计费边界。

## 用户充值商城

所有已登录用户（包括简单模式用户）以及管理员的个人功能菜单固定提供 `/recharge-store`“充值商城”入口，位置在“购买订阅”之后、“我的订单”之前，并与原生支付功能并存。该入口直接在独立 iframe 页面加载 `https://catfk.com/shop/baiyuapi`，不依赖 `payment_enabled`，也不复用自定义页面的 `buildEmbeddedUrl`。

商城属于不受信任的第三方页面，安全边界固定如下：

- iframe 和“在新窗口打开”按钮都使用未经改写的固定 URL；
- 不附加 Sub2API Token、用户 ID、`src_url`、`src_host`、主题或语言参数；
- iframe 使用 `referrerpolicy="no-referrer"`，但不设置会破坏第三方支付、脚本或弹窗流程的 sandbox；
- 应用 CSP 只放行精确来源 `https://catfk.com`，不得扩大为通配域名；
- 内嵌不可用时由页面明确提示用户改用新窗口，不在 Sub2API 内代理支付请求。
- 页面会在 iframe 加载期间提供状态反馈；加载较慢或失败时保留原始商城链接作为恢复路径。
- 移动端不尝试跨域改写商城内部布局，改为提高嵌入视口、避免宿主页面再次截断内容，并明确建议使用新窗口完成商品选择和支付。

该功能不新增设置、数据库字段或迁移；商城 URL、菜单名称和路由属于 fork 产品合同，变更时需要同步前端测试、CSP 测试和 fork extension catalog。
