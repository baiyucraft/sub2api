# sub2新站参考能力迁移边界

本页记录 `.upstream/sub2新站` 作为旧版参考实现时仍然有效的长期工程边界。该目录不是当前官方 `upstream/main`，也不是可以直接合并的 Git 历史；任何能力迁移都必须以当前 fork 和目标官方主线为底稿逐符号实现。

## 来源性质

- 参考实现基于官方 `0.2.4`，当前 fork 已进入 `0.2.5-baiyu` 系列。
- `sub2新站` 与 `sub2新站-1` 的业务源码基本相同，后者不作为独立实现来源。
- 参考目录中的发布清单存在漂移，不能单独作为源码身份；需要重新计算目录树摘要并核对具体文件。
- 参考实现中的 migration 编号、Ent/Wire 生成物、网关大文件和前端大组件都不能原样复制。

## 能力处置

| 能力 | 长期处置 |
|---|---|
| `X-Codex-Turn-State` 捕获、透传、同账号复用和跨账号防污染 | 当前 fork 已具备，保留当前实现，不重复迁移 |
| 账号保护策略、预览、原子应用/还原和字段 ownership | 可按独立 change 参考实现，必须补事务和并发回归 |
| HTTP、WSS 与账号测试身份统一 | 以当前身份和调度链为底稿逐函数合并 |
| Mode1 请求语义完整性守卫 | 先 observe-only，再基于误报证据决定是否 enforce |
| 连接池按身份、代理和 TLS 配置隔离 | 在当前 WebSocket reader、ping 和保活实现上增量加入 |
| Node.js 风格 TLS 模板 | 仅作为可选账号策略，不改变默认传输，不承诺规避风控 |
| 动态 RPM、burst、动态并发和错误反馈 | 只能扩展现有统一准入，禁止并存两套权威计数器 |
| 智能能力测试、队列、评估和管理 UI | 作为独立模块迁移，重新分配 migration，并与业务请求共享容量 |
| 多地区 IP 测试、质量结果绑定 Turn State、40-45 分钟轮换 | 参考实现并未提供完整能力，必须单独立项验证，不属于直接迁移 |

## 禁止整文件覆盖

以下范围必须进行语义合并，禁止用参考实现整文件覆盖当前 fork：

- OpenAI gateway、Responses、Chat、Messages 和 Images 请求链；
- scheduler、并发准入、失败切换和 WebSocket pool/forwarder；
- Ent schema 与生成代码、Wire 生成代码；
- 账号 repository/service/handler 与管理后台账号编辑组件；
- 完整配置文件、迁移目录和发布资产。

参考实现基于旧主线，整文件覆盖会丢失官方修复以及 fork 的 RPM、探针、上游同步、分组优先、容量切换、平台扩展和监控合同。

## 统一准入与身份边界

1. 一次真实上游尝试只能经过一个权威 RPM/并发准入点并计数一次。
2. HTTP、WebSocket turn、兼容协议、Images 和账号测试必须使用同口径身份与容量规则。
3. failover 切换账号后，不得携带旧账号生成的 Turn State、连接身份或缓存状态。
4. 不同账号、代理、TLS 模板或保护身份不得错误共享连接。
5. Redis 故障的 fail-open/fail-closed 行为必须沿用当前正式合同，不得由参考实现隐式改变。
6. 智能测试不得刷新 OAuth、切换代理、修改账号配置或污染生产健康和调度状态。

## 迁移顺序

每项能力必须独立设计、测试和提交，推荐顺序：

1. 账号保护领域模型与原子应用；
2. HTTP/WSS/账号测试身份统一；
3. 语义完整性 observe-only；
4. 连接兼容键和可选 TLS 模板；
5. 在现有准入上增加 burst 与动态并发；
6. 语义完整性 enforce；
7. 智能能力测试及管理后台；
8. 另立研究项目验证多地区 IP、Turn State 与质量关联假设。

## 每阶段门禁

- 先重新读取当前 migration 尾号、release profile、官方目标 SHA 和 fork 扩展目录，禁止沿用旧阶段候选编号。
- 高风险共同路径逐块 review，并保留当前 fork 专项回归。
- 账号保护、身份、语义、连接、流量和智能测试分别建立 normal、failure、boundary 测试。
- 完成本地 Go 测试、unit-tag 测试、前端测试、类型检查、ESLint、生产构建和 `git diff --check`。
- 涉及后端、配置、共享契约、构建链或数据库时必须通过当前提交对应的 VM Gate。
- VM Gate 通过不代表生产发布；生产变更必须走单独发布与验证流程。

## 维护规则

参考目录只提供设计证据，不自动成为 fork 合同。能力真正落地后，才在 `extensions.yaml` 登记路径、符号、迁移、测试和 invariants，并把稳定运行语义补充到本 Wiki。一次性对比数字、临时 SHA、执行日志和阶段任务不进入长期知识页。
