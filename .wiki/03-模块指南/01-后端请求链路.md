# 后端请求链路

```text
main -> runMainServer -> initializeApplication -> ProvideRouter -> SetupRouter -> registerRoutes -> handler -> service -> repository/upstream
```

`main.go` 处理 setup、迁移和版本；`wire_gen.go` 组装 config、Ent/SQL、Redis、repository、service、handler；`ProvideRouter/SetupRouter` 配置 trusted proxies、recovery、日志、CORS、安全 headers、session binding 和嵌入式前端；`registerRoutes` 注册 common、`/api/v1`、gateway、payment 和 page routes。

handler 负责协议/DTO，service 负责业务策略，repository 负责数据库、缓存和外部连接；避免 handler 直接访问 Ent 或生产网络。

## 分组模型白名单拒绝记录

分组模型白名单按客户端请求模型执行准入，拒绝仍返回 404。只有 `model_not_allowed` 入口拒绝进入现有 `ops_error_logs` 的业务拒绝记录路径；无效 Key 等其他入口拒绝继续使用有界入口聚合，不写常规请求错误日志。原入口拒绝聚合保留。

HTTP 拒绝点和 Responses WebSocket 首帧、后续轮次传递明确的安全元数据，记录实际未命中的模型、请求当时的分组 ID、用户与 Key 标识、接口和请求关联信息。记录不从响应文案猜测模型，不保存请求体、提示词、工具参数或完整凭据，不使用上一轮的账号、上游模型和上游错误上下文。一个被拒轮次只记录一次；WebSocket 后续轮次不能被连接级的已记录状态吞掉。

拒绝条目的分类固定为 `type=model_not_allowed`、`phase=request`、`owner=client`、`source=client_request`、`is_business_limited=true`；未发送上游时账号及上游归因保持空。它计入业务拒绝和总请求口径，排除在 SLA 故障数、SLA 故障率及上游故障统计之外。记录复用现有有界异步队列、丢弃监控和日志留存规则，不承诺队列溢出时逐条无损。

管理端错误查询支持精确筛选 `reason=model_not_allowed`，并与分组、客户端模型和时间范围组合；拒绝原因筛选使用业务拒绝视图，避免与默认故障视图相互排除。没有保存模型和分组维度的历史入口聚合不能回填成请求明细，也不能把当前 Key 绑定分组当作历史分组。

本功能复用既有日志字段，不增加数据库迁移、release profile 或生产配置开关。实现提交与本地测试不表示正式 VM Gate 或生产发布已完成。
