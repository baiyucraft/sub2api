# 跨平台上游可信度探针

可信度探针面向支持主动探测的上游 API Key 账号，复用现有健康探针周期，不增加自动上游请求。OAuth 与服务账号不纳入模型归因。结论只用于管理诊断，不改变健康状态、账号可用性、停用策略或调度权重；连通性、鉴权及协议失败仍由原健康探针处理。

## 统一结论与证据边界

列表和详情统一使用 `health.confidence_summary`，替代对外的 `confidence_distribution` 与 `confidence_attribution`。摘要包含 `status`、`target_model`、`effective_model`、`candidate_model`、`reason`、`fusion_version=1`、`inference` 与 `methods`。状态只有 `collecting`、`insufficient`、`match`、`suspected`；页面只展示一套可信度结论，方法明细用于解释结论，不再同时展示互相割裂的旧摘要。

目标模型取当前平台配置，实际模型取生效映射。平台、模型和协议必须匹配方法的精确适用范围，不使用其他平台或相似型号的基线。若目标模型与实际映射模型不同，返回 `insufficient / target_model_mismatch`，不把映射当成模型伪装。`match` 与 `suspected` 均相对于目标模型；只有分布方法允许 `other` 候选。无适用基线、样本无效、状态不可用及方法冲突都不能生成身份结论。

协议证据是独立维度。协议不兼容不能转换成模型不匹配；单次答案、自报模型名、算术正确或 JSON 合规也不足以证明身份。所有分数都是方法内部的统计或相似度量；统一结果是工程推断，不是身份认证或模型身份概率。

## 方法门槛与融合

| 方法 | 工程默认权重 | 参与条件 |
| --- | ---: | --- |
| 128 条分布 | 3 | 既有完整有效窗口、配额、校准阈值及协议基准校验全部通过 |
| ModelTrace 数字 | 2 | 完整三挑战；封闭候选集第一名支持度至少 0.80，且第一名减第二名至少 0.65；两个完整不重叠轮得到同一候选 |
| Chanshui 行为 | 1 | 完整三挑战；第一名余弦相似度至少 0.88，且领先第二名至少 0.03；两个完整不重叠轮得到同一候选 |

3／2／1 是本项目的工程默认权重，不是对三个方法准确率的实测估计。两套参考数据尚无跨方法独立联合验证；阈值和权重不能描述为已经统计校准的身份置信度。ModelTrace 的 `relative_fit`（JS 相对拟合）不参与数字方法门槛；封闭集支持度也不能称为模型身份概率。

只有通过各自门槛的方法才参加推断；未通过的方法 `effective_weight=0`，明细仍保留其进度与安全原因。`methods` 增加 `weight`、`effective_weight`、`participating`、`candidate_model` 与 `confirmed_rounds`。参考方法必须以两个完整、不重叠且身份一致的轮次确认同一候选，不能把相邻滑窗、同一轮重读或幂等完成算作第二轮。序号、方法、基线及系列必须匹配，失败和不完整轮不能补用旧响应凑数。

参与候选必须一致且总有效权重至少为 3。合格分布方法可单独形成结论；没有分布结论时，必须由数字和行为两种方法分别完成两轮并支持同一候选（2+1），此时 `inference=true`。只有数字或只有行为证据仍然不足，不能因排名第一直接给出模型身份结论。满足这些条件后才生成相应的目标匹配或疑似替代结论；有效候选冲突时返回证据不足，权重更高不能抹去冲突。没有可参与的方法时按采集中或不足原因展示；方法细项始终能解释哪个门槛未满足。管理 GET、自动刷新和时间自然推进不能制造新的确认轮次。

## 采样与请求合同

探针型号沿用每平台统一配置，不增加账号级覆盖。`confidence_probe.model_selection_version` 缺失或为 0 的旧启用配置继续显示并实际使用 `gpt-6.1-sol`，读取不写迁移；明确保存设置或模型选择后，以版本 1 使用所选型号。请求构造、系列身份、读取和评分使用同一目标快照，账号映射后的实际型号另行记录；目标与实际型号不一致时不得输出匹配结论。

OpenAI 有适用分布基准且没有参考基线时，每个既有探针机会都采分布样本。两类都适用时，每十次机会恰有九次分布挑战、一次参考挑战，参考方法按区块轮换；该次位置由持久化序号和系列身份确定，重启可复现。只有参考方法适用时，在适用参考方法间轮换；两类均不适用时继续普通健康探测并保存最近协议证据。其他平台同样只在存在适用参考方法时使用原健康周期采对应挑战。一次 claim 消耗一个排程位置；失败不立即补发，单次响应不得同时计入两个方法，在途 attempt 的方法不能由回退路径改写。

每种参考方法以独立持久化序号组成三挑战区块，只用本轮完整、未过观察保留期的证据。新区块显示真实进度，不能把旧排名当作本轮的新证据。行为与数字方法的两轮确认独立于分布的 128 条滚动窗口，不重置已满的分布窗口，不要求重新采集已有有效 128 条。

参考挑战使用固定来源文本，不注入健康探针最小输入填充或 Claude Code system，不强制温度。Chanshui 输出预算为 2,048 tokens，ModelTrace 为 4,096 tokens；流式与非流式解析保留特征依赖的空白和换行。空回答、HTTP/协议失败、截断、拒绝及内容过滤结果不计为有效参考样本。ModelTrace 三挑战请求 292／308／324 个整数，按 `max(80, ceil(expected_count × 55%))` 至少解析 161／170／179 个有效数字，三条均有效后才能评分。

协议证据独立保存最近一条，不占行为样本容量。旧 JSON 缺少采样策略版本时保留原样本、递增序号和有效租约；有效旧租约按其持久化方法完成。无适用参考基线时显示已采集数和“暂无适用基线”，不显示误导性的行为样本门槛。

## 系列身份与持久化

内部 distribution 与 fingerprint 状态和历史样本继续保留，各自使用独立 revision/CAS 和租约，避免健康写入覆盖采样。系列绑定 Key/账号、平台、实际映射模型、协议、规范化端点和凭据身份摘要、挑战/归一化/评分合同及基线版本。自适应国产协议以已配置端点集合保持稳定系列，每条样本另存实际路由协议，不把不同协议证据混为同一适用基线。

配置、身份或算法版本变化后重新验证相关参考轮次；旧 JSON 不得凭空补成已确认。明文凭据、代理密码、原始认证头和原始回答不持久化，状态仅保存行为特征或已解析数字及必要元信息。保留既有观测保留边界、租约竞争和幂等校验；采样读取或完成失败不影响普通调度。

## 基线来源与维护

资产随版本内置，运行时不联网更新；新增型号需先确认精确标签和协议范围，未覆盖时保持未知。

- 行为聚合画像的参考入口为 [Chanshui 固定提交](https://github.com/kiss-kedaya/chanshui/commit/2e23eeac864a7c7f5cb0fe0574215c903cd7a7f7)。其 `data_ref/probe_v3e_snapshot.json` 记录的数据源为 `@bazaarlink/probe-engine` / `openruterati` 的生产 `submodel_baselines_v3`，采集说明为 2026-08-07 benign ladder。现有 34 条是聚合画像，未包含可用于独立核验的原始分组样本；不能写成已在本项目重新采样校准。
- 数字参考库来自 [ModelTrace 固定提交](https://github.com/xqy2006/ModelTrace/commit/6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2)，含 18 个模型、648 条样本。它和上述行为画像来源不同，没有证据表明两者经过独立联合验证。

来源提交、原文件、数据时间、版本和校验值随资产登记。Chanshui 的[第三方说明](https://github.com/kiss-kedaya/chanshui/blob/main/THIRD_PARTY_NOTICES.md)与项目所有者确认的自用内置范围分别记录，不把代码许可推导为第三方数据通用再分发许可。`gpt-6-sol` 条目不能替代 `gpt-6.1-sol`；两套参考库缺少后者精确条目时，只能使用其真正适用的独立分布证据。

分布算法、原题、配额、基准来源和 128 条有效窗口仍由[专项指南](./12-OpenAI-Sol分布可信探针.md)维护；统一推断只改变对外聚合与诊断表达。回归覆盖方法门槛、两轮确认、冲突、目标映射、未知基线、旧状态、在途租约、单周期请求数量，以及页面只使用统一摘要。定向单测和版本登记不等于 VM Gate、生产部署或模型准确率验收。
