# 跨平台上游可信度探针

可信度探针面向支持主动探测的上游 API Key 账号。它复用现有上游健康探针调度周期，不额外增加自动请求；OAuth 与服务账号不纳入模型身份归因。探针只提供管理员诊断证据，不改变账号健康状态、账号可用性、停用策略或调度权重。连通性、鉴权及协议失败仍由既有健康探针处理。

## 证据边界

- 模型归因和协议证据是不同维度。协议不匹配只能说明请求/响应合同不兼容，不得推导为模型身份不匹配。
- 指纹必须匹配平台、协议和目标模型的已审核基线。无基线、基线不可用或证据未达要求时返回 `unknown` / `insufficient`，不得借用别的平台基线。
- 单次答案、自报模型名、算术正确、JSON 格式正确或通用挑战通过，都不足以证明模型身份。
- 指纹输出保留方法、状态、样本数、最低样本数、基线版本和安全原因；协议输出单独携带协议及协议状态。

## 采样与 OpenAI 结论

非 OpenAI 平台从已有健康探针请求及同一响应中提取适用行为证据。只有通过请求完整性校验的响应才可进入指纹样本；健康探针失败的处理保持原语义。现有 OpenAI 128 条有效样本分布探针与指纹采样在同一 Key 的既有周期内轮换，避免新增上游请求。轮换会拉长原分布探针窗口达到 128 条有效样本所需时间，不改变窗口配额。

OpenAI 对外给出一个融合状态，同时保留各方法证据：两方法充分且一致时为相互印证；仅一方法达到有效样本要求时给出暂定结论；充分结论冲突时标记待复核；两者均不足时显示证据不足。融合只描述行为证据，不是身份概率，也不进入健康或调度控制。

## 系列身份与持久化

跨平台指纹状态与健康观测、OpenAI 分布状态机分别持久化，使用独立 revision/CAS 与租约，避免健康更新覆盖采样进度。系列身份绑定 Key/账号绑定、平台、实际映射模型、请求协议、规范化端点身份摘要、凭据身份摘要、挑战/解析/归一化合同版本及基线版本。自适应国产协议使用稳定的配置系列身份，绑定全部已配置路由端点；每条样本另记录本次实际协议，避免路由回退造成状态重置或把协议维度混在一起。身份变化必须创建新系列；明文凭据、代理密码和原始认证头不得写入状态或日志。

跨平台扩展使用独立迁移 `304` 和 profile `277`（parent `276`，版本 `0.2.19-baiyu`），不得改写迁移 288 或其历史 profile。旧设置 JSON 保持兼容，管理 API 采用可选的 additive `confidence_attribution` 摘要；旧客户端缺字段时仍可照常展示原有 OpenAI 分布信息。

## 基线与维护

基线随项目版本内置，运行时不联网同步。当前没有同时通过许可审核与独立留出验证的跨平台行为基线，因此新采集的行为样本只用于呈现覆盖数，模型归因保持 `unknown`；协议兼容状态仍可单独呈现。新增某个平台基线前必须检查数据许可，记录来源、平台/协议/模型适用范围、采集时间、训练样本与独立留出样本、版本和校准结果。当前 Chanshui 参考提交为 [`2e23eeac864a7c7f5cb0fe0574215c903cd7a7f7`](https://github.com/kiss-kedaya/chanshui/commit/2e23eeac864a7c7f5cb0fe0574215c903cd7a7f7)。可借鉴它按证据维度呈现指纹和未知状态的思路，不复用 IQ/缓存/工具等综合分作为身份结论，也不直接复制未完成许可审核的第三方指纹数据。Chanshui 的 MIT 代码许可不覆盖第三方数据，见[第三方说明](https://github.com/kiss-kedaya/chanshui/blob/main/THIRD_PARTY_NOTICES.md)。

旧的 OpenAI Sol 128 样本算法、请求合同、基准许可说明和持久化行为仍由[专项指南](./12-OpenAI-Sol分布可信探针.md)维护；本指南不重定义它们。
