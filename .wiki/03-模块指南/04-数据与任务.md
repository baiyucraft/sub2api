# 数据与任务

Ent/schema 覆盖用户、组、订阅、API Key、账号、渠道、用量、审计和运维；repository 封装 Ent、原生 SQL 和 Redis。生成 Ent 文件是派生输出，长期合同来自 schema、迁移和 service/repository 接口。

Redis 承载 auth cache、限流、并发、调度快照、Token/session、队列和临时不可用状态。备份、S3/image storage、恢复、定时测试、配额同步和监控任务属于管理面；外部存储、整库覆盖或凭据导出受 step-up 和部署恢复门禁约束。

上游健康观测以 `source=probe` 保存主动探针证据；真实流量证据仍按 `LastEvidenceAt` 参与普通后台探针 freshness 抑制。可信度统计只读取新 Juice 版本且只用有效完成响应，网络异常、HTTP 错误、超时、流中断和无返回不进入分母。旧可信度字段清理必须幂等，并保留同一观测中的普通健康、HTTP、TTFT 和时间证据。相关长期合同见[分叉扩展与兼容性](./05-分叉扩展与兼容性.md)。
## 邮件收件域名路由

系统邮件统一经 `EmailService.SendEmail` 发送。主 SMTP 是默认 profile；管理员可启用收件域名规则（精确域名或 `*.example.com`）并配置独立 QQ SMTP。命中规则且 QQ profile 完整时使用 QQ 发件地址，未命中、路由关闭或 QQ 配置不完整时使用主 SMTP。

QQ SMTP 的连接、TLS、认证、MAIL 或 RCPT 阶段失败可以回退主 SMTP；DATA 阶段已经开始后结果可能已投递，禁止再次发送以避免重复邮件。settings GET 只返回 `smtp_*_password_configured`，空密码 PUT 保留旧值。日志仅记录 profile、阶段和收件域名哈希，不记录凭据、完整地址或正文。

## 管理员账号 JSON 导入

`POST /admin/accounts/data` 在未提供 `copy_proxy_ids` 时保持原有导入语义。提供复制代理槽位后，批次中的每个源账号按槽位顺序创建副本，一个槽位绑定一个当前可用代理；重复选择同一代理是允许的，且不额外保留未绑定代理的原账号。副本名称由后端生成：`原账号名 - 代理名`，代理名为空时使用 `host:port`，超过 100 个字符的副本单独失败。

`override_concurrency`、`override_rate_multiplier` 和 `override_codex_fingerprint_mode` 采用“填写即覆盖、未填写保留”规则，数值 `0` 是有效覆盖值。复制账号会深拷贝凭据、扩展数据、备注和有效期；Codex 指纹种子永远由创建服务按账号独立生成，不从导入 JSON 复制。指纹模式仅对 OpenAI OAuth/Setup Token 生效，支持 `off`、`device`、`session`、`full`。
