# 上游缓存保护

管理入口是上游管理设置的“上游缓存保护”和分组的统一“上游保护”弹窗。`GET/PUT /api/v1/admin/upstream-management/settings` 的 `cache_guard` 配置默认 `mode=disabled`；全局 `observe` 只收集和展示，`protect` 才参与调度。分组自定义 `enabled` 独立进入保护，不受全局 `disabled/observe` 限制；旧客户端省略该字段时保留已有配置。

分组列表的“调度保护”入口在点击、窗口重新聚焦、页面恢复可见和设置更新时刷新平台范围。刷新期间保留上次成功的范围和按钮位置，避免按钮短暂卸载导致相邻“专属 RPM”进入鼠标悬停态；成功后统一更新范围和策略摘要。打开弹窗仍等待最新校验；最新读取失败或接口不可用时隐藏入口并关闭弹窗，平台移除时关闭对应弹窗，过期响应不得覆盖较新结果。回归覆盖 `GroupsView.ttftGuard.spec.ts` 与 `GroupUpstreamProtectionPolicyModal.spec.ts`。

## 配置与判定

`scheduling_protection_platforms` 是 TTFT 与缓存保护共用的全局平台范围，存储在现有 settings 中，无新增 SQL 迁移。缺键默认 `["openai"]`，旧客户端 PUT 省略字段保留已保存范围，显式 `[]` 表示全部停用；值按具体平台清单校验、去重并稳定排序，不接受 `composite`。分组平台和实际账号平台均须纳入范围，分组自定义不能绕过。取消选择后停止保护择优、软迁移和恢复准入，保留共享事实及原分组配置；重新选中后按现有窗口与有效配置判定，不扩展平台原有 TTFT 能力。停用前已发送的请求仍确认持久化终态，合法事实保留在共享窗口，但暂停标记排除其恢复样本身份；发送前取消的迁移保持原绑定并交回重选。

分组缓存策略支持 `inherit/enabled/disabled`。自定义只允许保护阈值、恢复阈值和最小有效请求数，窗口、冷却、试用比例和保护证据有效期继承全局；`enabled` 即使全局关闭或仅观察也独立 `protect`。全局调度优先策略为 `cache_first/ttft_first`，默认 `cache_first`，分组另可选择 `inherit`。策略采用明确分层排序，不能转换为加权总分。

`GET /api/v1/admin/groups/upstream-protection-policies` 与 `GET/PUT /api/v1/admin/groups/:id/upstream-protection-policy` 返回和保存 TTFT、缓存及优先策略；一次 PUT 在同一事务更新两个 fork 表与 scheduler outbox。旧 TTFT API 继续兼容。迁移 298 保留旧缓存 `group_ids` 配置，将非空白名单选中组初始化为继承、未选中组初始化为停用，重放不覆盖已有自定义策略。

| 字段 | 默认值 | 合同 |
| --- | --- | --- |
| `mode` | `disabled` | `disabled` / `observe` / `protect` |
| `group_ids` | `[]` | 旧白名单仅保留作旧镜像回滚兼容；新 resolver 使用分组策略，不再以此字段限制执行 |
| `threshold_percent` | 75 | 有效窗口率严格低于该百分比触发保护 |
| `window_minutes` | 60 | 5–1440 分钟 |
| `min_valid_requests` | 20 | 有效请求数严格大于门槛后才判定，20 次不足、21 次满足 |
| `recovery_threshold_percent` | 80 | 必须高于保护阈值；达到该值才可恢复 |
| `cooldown_minutes` | 10 | 保护后进入下一轮恢复试用前的冷却时间 |
| `trial_percent` | 10 | 分组总体自然新会话的试用比例，按会话固定，不能解释为每账号或每请求 10% |
| `protection_evidence_expiry_minutes` | 15 | 1–1440 分钟；保护账号连续超过该时间没有有效续聊样本时转为未知并回普通调度；旧 JSON 缺字段或值为 0 按默认值读取 |

统计身份固定为上游账号 ID 与当前上游 Key ID，不区分分组、模型或协议；所有分组的有效事实合并，各组再按自身有效策略投影执行。换 Key 后旧证据不能继承。缓存率为有效样本缓存输入 Token 总数除以全部输入 Token 总数，采用 Token 加权而非逐请求或逐组百分比平均。正常样本与恢复 cohort 独立统计；冷启动首轮、失败和缺少有效用量的样本不参与判定。未知率不是 0%。这是业务缓存利用率，不能仅据此证明上游故障。

缓存保护的有效续聊窗口与质量列的全部成功请求统计使用不同样本集合和时间窗口，两者百分比不要求相同。仅声明 `image_generation` 工具不排除文本请求；显式选择该图片工具或实际产生图片的业务仍排除缓存采样。入队前的 admission 跳过按固定原因累计，首次及每千次记录聚合日志，仅含原因、累计次数、分组和账号 ID，不含正文、凭据或会话标识。

常规运行中，进入保护、恢复正常及试用失败后重新冷却的判定由新处理的有效事实触发。该事实须仍在当前统计窗口内，且晚于账号的质量重置时间；是否有新事实不按窗口净计数或最新完成时间推断。迟到事实即使与旧事实过期相抵、有效请求数不增加，仍重新判定保护及当前试用周期；最新证据时间保持单调。纯窗口过期重算只更新计数与缓存率，不触发进入保护、恢复正常或重新冷却；幂等重放已处理事实也不重复计数或触发判定。首次创建账号级状态是例外：汇总仍有效的旧已处理事实后，若满足门槛立即统一判断是否保护，不等待新请求；旧恢复 cohort 不作为恢复依据。

有效续聊须有可靠逻辑会话标识：明确白名单会话 header、正文 `prompt_cache_key` 或可解析的 `metadata.SessionID`。统计会话摘要与调度 sticky hash 独立；OpenAI 按内容生成的 fallback、Anthropic/Gemini 全消息 hash、Gemini 项目临时目录 hash 和缓存句柄均不足以证明同一会话，不用于预热或迁移判定。没有可靠 marker 的请求在 `observe` 和 `protect` 下同样不形成有效续聊；结果显示样本不足或未知，不能当作 0% 缓存。

暖上下文按实际上游协议分别预热：OpenAI HTTP、OpenAI WS、原生 Anthropic 和 Gemini 各自独立。选号须读取入站经过适配后实际要发送的协议；OpenAI 接口经原生 Anthropic 转发不能拿 OpenAI 暖上下文判定迁移。WS 每轮有独立 request identity；只有真正发送的业务请求冻结 admission，终态完成后记录原始上游缓存证据。终态缺字段不继承先前帧的缓存值，缺字段与明确 0 区分；失败、不完整流和客户端断开不形成成功样本。

原生 WS 与 HTTP/SSE 共用终帧用量解析规则：终帧缺 `usage`、缺缓存字段或全部为 0 时，缓存事实仍以该终帧独立覆盖先前证据；WS 入口须让无 `usage` 的终帧进入共享解析器，普通非终帧继续使用热路径过滤。原计费在终帧全 0 时保留同轮已有非零 Token 的回退策略不变。解析生成新事实对象，后续帧不得修改先前对象。入站 WS 和 HTTP bridge 将已知客户端断开状态传递到每轮结果；断开后继续 drain 可保留计费 Token，但不形成缓存样本。裸 `error` 保留失败终态，不能归一成表示旧兼容成功的空终态。图片工具合法用量继续原子优先覆盖图片计费，图片业务本身排除缓存保护；异常图片终帧不得覆盖既有计费 Token，也不能形成有效文本缓存样本。

完成判定使用真实上游终态和业务输出结果。Anthropic 转换流只有收到 `message_stop` 且读取与客户端输出未失败才形成有效样本；转换器在 EOF 时补给客户端的结束事件不能代替上游终态。Gemini 原生、Messages 和 Chat 三条流均要求成功的 `finishReason`，并独立记录全部输出写入失败，包含最后的结束帧；已有用量及原响应、计费排空策略保持不变。取消与断流即使随后读取到合法高缓存用量也不形成有效样本。

OpenAI HTTP 原生 Responses、透传及 Chat/Messages 转换入口保留改写前的同帧原始用量；后续 typed 计费用量复制和错误脱敏不覆盖该证据，也不从缺失字段的零值推断明确零缓存。终帧独立决定字段是否合法，不能沿用先前帧的 Known。原生 Chat 的 usage-only 帧不能证明完成，需有结束标记或正常 `finish_reason`；`length`、Gemini `MAX_TOKENS` 和 Anthropic `max_tokens` 属于正常预算结束，在用量合法且流完整时仍可计入。`content_filter`、error、Responses failed/incomplete/cancel 和客户端断开均排除；正常 `error:null` 字段不误判为失败。

WS 透传的单轮完成观察发生在该终帧客户端写入返回后、下一轮生命周期释放前。写入失败或已进入断流排空的单轮仍保留一次计费回调，缓存事实复制后标记为不完整，不修改此前事实对象；adapter 同时传递客户端断开标记。不能只用上游已完成或回调已触发证明业务流成功。

客户端已读到终帧与服务端完成回调提交之间仍可能存在调度间隙。`openai_ws_passthrough_turn_pricing_test.go` 的续轮合同须同步到实际 `AfterTurn` 事件后检查两轮回调和各轮计费，并保留 `BeforeRequest` 先于 `BeforeTurn` 的顺序断言；不得以立即读取客户端终帧代替完成屏障，也不得把生产观察时机移回客户端写入之前。

## 账号级判定与分组执行

原始账号事实与窗口共享，保护 phase、冷却截止、恢复 cohort 和重置边界由质量签名投影维护。质量签名包含保护阈值、恢复阈值、最小有效请求数和有效证据期限；默认 15 分钟沿用已发布的 v1 签名，保留旧保护、恢复 cohort 与 admission 身份，非默认期限使用包含期限的 v2 签名。相同规则的组共享同一投影，不同规则独立。签名不包含分组、模式或优先策略。有效 `observe` 只展示，不改变调度；有效 `disabled` 不执行保护。各组仍独立维持会话绑定、协议暖上下文、候选池、容量与分组总体自然新会话试用比例，不跨组混合会话或分配配额。

保护相位 `cooling/trial/degraded` 连续无有效样本严格超过配置期限后转为 `unknown`，清除冷却与恢复控制，停止保护排序、新增试用和软迁移，按普通调度处理；时间恰好等于期限仍保留原状态。按最近有效证据时间计算，旧状态兼容降级锚点；管理读取和每秒成功核验不延长期限。过期不是通过恢复验证，也不会自动标为健康。过期时保留证据重验边界，旧低缓存窗口重放不能重新触发保护；新的有效证据到来后仍按原窗口、严格样本门槛和阈值重新判断。读快照时即时判断过期，不等待后台刷新。

旧分组状态首次迁移时在账号锁内保守汇总当前 Key 与质量重置边界之后的窗口事实；任一旧分组处于保护/恢复则继承保护，并使用最晚冷却截止。旧顶层账号质量状态保守迁入匹配全局阈值的投影，新自定义阈值不得借用旧恢复试用证据。事实事务以账号/Key 上锁、幂等确认并保持固定锁序；快照按下述账号级新鲜度合同降级，不把未知当低率，也不因尚未初始化而自动解封。

每个账号与当前 Key 独立保存最后成功投影的快照和成功时间。年龄不超过 5 秒时可参与全部缓存保护决策；超过 5 秒但不超过 30 秒时只保留已有会话偏好，不新增恢复试用或软迁移；超过 30 秒或从未取得成功快照时退回普通调度。年龄始终从该账号最后成功时间计算，读取旧值不续期，Key 轮换不复用原 Key 的快照。

尚未建立任何账号状态的当前账号与 Key 允许初始化采样，但必须同时不存在账号快照、刷新版本和逐账号策略代次记录，且没有采样 gap 或失败标记。仅当最近成功刷新确认的策略代次等于当前策略代次，并满足原有 5 秒新鲜条件时，才允许首次同步准入；该例外不生成缓存率或伪造有效样本，也不复用其他 Key 的证据。已有状态、旧策略或失败身份仍按原快照规则保守处理。首次请求继续冻结为冷请求，后续符合条件的温热续聊才计入有效样本；不回填历史请求。回归入口为 `bootstrap_snapshot_test.go` 和 `upstream_cache_guard_bootstrap_test.go`。

单账号投影失败或出现采样 gap 时，保留该账号最后成功快照与原成功时间，不把失败时间写成新成功时间，也不影响其他账号。全局刷新失败时，各账号仍按各自最后成功时间独立进入上述阶段，不能由 runner 的全局 unavailable 标记同时撤回全部账号偏好。全局 pending 数量、最老 pending 年龄及其查询失败仅作诊断，不成为整批账号保护熔断条件。

## 会话与可用性

保护账号给自然新会话让路；仍高缓存或未连续两次有效续聊低率的旧会话保留。允许迁移的旧会话连续两次有效续聊低率后，下一次才尝试迁移：目标的有效窗口率至少高 5 个百分点，并且实际具备容量。取得失败保留原账号，不提前改写绑定。迁移后的冷首轮不计入有效续聊，成功迁移后最短驻留 5 分钟。

软保护迁移、缓存恢复 cohort 和 TTFT 试用发送标记在实际 transport 发送前的最终准入点提交。`protection_send_admission.go` 的一次性 callback 在本地请求准备、插件/利润准入和取消检查通过后固定绑定；目标账号或当前 Key 改变即拒绝。发送前拒绝不迁移、不启动 cohort、不计试用发送；同账号重试与 WS turn 复用一次性提交边界。恢复样本还须符合完成和有效用量合同，不能把选号或准备发送当作有效恢复证据。

## TTFT 调度保护合同

TTFT 运行时保留在 service owner 的内存 map 与 mutex 中，显式携带 `runtime_id`、算法版本和策略代次；重启后旧票据和旧恢复证据均视为未知。不会为 TTFT 新增 Redis/SQL 权威状态，也不承诺短暂双实例期间跨进程即时一致。坏证据有固定有效期，过期后状态回到 `insufficient`/待验证；普通快流量不会续期坏证据，也不会把没有新事实自动恢复为正常。

TTFT 质量读取使用三态：`normal`、`protected` 和 `insufficient`。同一质量签名可共享原始观测与恢复进度，试探预算仍按 `group_id + canonical model` 独立计数。质量分层在每个相同优先池内先于缓存收益排序；因此 `cache_first` 与 `ttft_first` 都不会让同池持续慢账号仅凭更高缓存率压过健康或样本不足账号。不同优先池、真实容量、健康、能力、利润和固定重试约束仍由原调度器执行。

普通业务完成事实才可推进恢复：连续至少 3 个成功快 attempt，TTFT ≤ 0.6 阈值，覆盖至少 2 个可靠逻辑会话，并通过发送、完成、运行时和策略代次校验。此恢复门槛独立于冷启动 min_samples；已经核心判为 normal 的 3 次恢复样本不会因初始化门槛为 20 被调度层重新降为 insufficient。事实按自身首 Token/完成时间进入有效窗口，重复 attempt 与同逻辑请求不重复制造恢复，发送早于最新坏证据、取消、失败、不完整终态和旧 runtime/代次不得恢复。后台查询、sticky 读取、固定同号重试、容量等待、未取得 slot 或诊断排除都不产生机会。试探用于补采样，普通流量同资格；每组每个模型以 20 次真实合法新分配取得一次信用，最多保留 1 个信用。信用公平轮转候选，unknown/insufficient 与 protected 均可试探；同一 runtime identity（账号 + 当前 Key + canonical model）最多 1 个试探在途。取得容量只预留票，实际 transport 发送才消费信用；发送前取消、缓存 cohort/数据库/范围准入失败或未发送会释放在途并归还信用。试探不能绕过缓存 cohort、数据库、平台范围、模型/Key 身份或利润准入。

不可迁移的 `previous_response` 绑定和固定同账号重试沿用既有语义。缓存保护不改变错误状态码重试配置。全组偏低时仍在硬合法、可调用候选池中择优；两种优先策略都先在同一优先池内比较 TTFT 质量，再比较缓存与负载；优先池顺序保持外层约束，策略不转换为加权总分。缓存或 TTFT 软限制不能新增“无账号”拒绝；分组权限、账号与模型能力、渠道和利润规则、额度、真实容量及本次请求失败排除继续生效。

## 恢复试用

冷却结束后，将分组总体自然新会话的配置比例分配给待恢复账号；多个账号轮转分配，单个会话固定账号，不使用逐请求抽签，也不新增多档流量阶梯。自然留存旧会话形成已有渐进过程。

每个账号试用周期只有一个恢复 cohort；启用分组的有效试用事实合并，观察时间从实际首个试用会话开始。未启用分组的普通事实只参与常规窗口，不替代试用验证。冷首轮不计，不能混入正常旧会话、冷却前或上一周期样本。同窗口有效请求数严格超过配置门槛、至少 3 个会话、缓存率达到恢复阈值且至少观察 10 分钟时恢复正常；样本充足且低于保护阈值时重新冷却；位于两阈值之间或数据不足时继续试用。

## 管理状态与隐私

## 调度保护性能与一致性合同

策略服务发布带递增 revision 的不可变快照，单组查询只复制该组值。成功读到相同内容只推进核验时间，不递增策略版本，不重复同步 TTFT 或清理策略投影。业务状态的 `updated_at` 与最近成功核验时间分离；后者只决定 5 秒 / 30 秒可用性，失败和页面读取不续期。

缓存引擎的 `CachedMetadataAt` 不枚举或排序账号，`CachedCandidatesAt` 仅投影本次候选；管理接口用 `CachedSharedAccountsAt` 一次短锁复制当前页，再在锁外克隆和生成各组状态。一次判定固定评估时间。轻量身份目录每秒核对账号、当前 Key、持久化状态版本和事实版本，只有变更、缺失、到达窗口边界或需重建的身份加载精确窗口。事实版本由兼容数据库 trigger 推进，包含 pending 新增、处理确认、只记录事实而不改变状态的分支和保留清理。发布前再核验版本、目录、策略代次及采样失败；旧计算不能给新状态续期或重新发布已删除身份。

带截止时间的后台刷新每轮最多处理 256 个待重建身份，按目录游标取连续尾段；实际策略物化只使用剩余预算的一半，为窗口读取和发布前确认保留时间。慢账号超时后游标仍推进，少于 256 个待处理身份也必须轮转，不能让后续账号饥饿。成功子集独立发布，未处理或失败身份不推进账号版本、策略代次或核验时间；确认失败则不发布本轮结果。每秒完整轻量目录和活跃会话核验不变，已确认未变的账号仍正常续核验。无截止时间的显式重建继续完整处理。

五分钟补充校验页的游标与日常重建游标独立：校验页只推进连续成功处理的身份，遇到延期或失败停留；只有完整目录实际核验结束才推进最近补充校验时间，不能因每轮 256 个处理上限而跳过 500 个校验页中的剩余账号。

仅因补充校验批次上限而延期、且本轮轻量核验确认事实/状态/策略和时间边界均未变化的账号，不形成采样 gap，仍可按未变化身份推进成功核验时间。实际版本或 Key 变化、采样失败、时间边界、时钟回拨、读取或发布确认失败继续阻止续期；不能把校验延期等同于采样缺口，也不能借此续期真正不确定的身份。该合同由 `bounded_refresh_test.go` 的延期未变化与变化/失败隔离测试覆盖。

策略代次按账号记录。共享原始缓存率与分组投影分别判断可用性：相同质量签名且窗口、冷却和试用参数兼容的组可在原 30 秒内沿用已有偏好，等待核验期间不标新鲜；新签名或不兼容口径在精确重建前必须未知，不能默认健康，也不撤回其他兼容组的原缓存率。只改变调度优先级可在轻量版本确认后恢复新鲜，不重复读取事实窗口。大规模旧数据冷启动可能跨多轮完成，报告必须列明完整账号收敛时间，不能只用单个账号就绪代表全量成功。

admission 只有在事实、状态、策略版本一致，且没有 pending/gap/cohort 变化、时间边界或时钟回拨时才复用核验过的精确投影。任何不确定都回到既有事实重算，时间推进本身不恢复健康。已有事实、质量签名、缓存率分母、严格比较和恢复条件保持原口径。

最近 30 分钟访问的会话驻留内存，历史身份仍保留在数据库。内存未命中按分组和会话主键冷加载；读取失败为未知，停止新增试用和软迁移，不能当自然新会话。完成 admission 仅在超过既有 48 小时后清理，未完成身份和仍参与判断的路线继续保留。每秒只读活跃/待完成会话的版本和变更行，不因历史行数触发运行态的全局容量上限；每五分钟按最多 500 个账号身份轮转校验作为一致性补充，不推迟正常变更刷新。

缓存保护专用数据库操作（会话冷加载、PlanTrial、admission 和 `CaptureOnly`）共用累计 100ms 活跃阶段预算；内存命中不启动预算，各阶段间普通计算不消耗预算，阶段并发通过租约串行消费剩余额度，调用方更短截止优先。耗尽记录 `upstream_cache_guard_budget_exhausted`，使用原业务请求预算回退普通调度。若已选定保护账号，发送前同步 admission 超时必须返回请求内重选信号 `scheduling_protection_budget_exhausted`，各协议转发不能将它改写成上游 502；重选不排除本账号、不消耗上游故障次数、不报告账号故障，并清除上次选择的保护和迁移标记。若发送前快照不可用，或陈旧快照原本用于新增试用/迁移，则以 `scheduling_protection_snapshot_unavailable` 请求内回到普通调度；仅禁止后续保护选号，不耗尽或重置剩余采样数据库预算，普通重选仍可同步 `CaptureOnly`。已有会话在容忍窗口内继续走 `AdmitExisting`，不能借陈旧状态创建新试用或迁移。WebSocket 已建立连接的后续 turn 保留物理连接，不能据此制造新迁移。试用序号和 admission 仍在发送前同步、原子、幂等保存，并先于 sticky 绑定提交；普通调度保留原有异常放行行为与硬约束。锁序为账号→会话→分组配额；无账号的规划为会话→配额，仅实际更新共享名额才加分组锁。

`PlanTrial` 对已经持久化且身份/规划未变化的会话只读取既有结果，不重写会话或配额、不推进其 version/updated_at；相同请求重试返回原计划，已有会话的新请求不再占自然新会话名额。并发首次规划仍由事务串行化，仅写入一次会话身份和一次自然配额。永久回归入口为 `backend/internal/upstreamcacheguard/plan_trial_noop_test.go`。

联合调度复用本次候选目录和 RPM/插件准入预取，各保护档位按原始账号顺序读取对应候选，保留 scope 外普通账号与原档位顺序。候选提示不跨请求缓存；最终槽位占用、当前账号/Key、模型、渠道、隐私、利润和其他硬约束仍沿用现有最新状态复核。保护档位失败后进入普通调度必须重新读取账号目录，不能再使用已被终检拒绝的旧候选。失败及时释放容量，最终选定前不写 sticky。

TTFT 使用账号+Key→模型、原观测→质量签名投影两个索引及有版本校验的过期堆。样本按自身时间重建有效窗口，EWMA 只读当前有效样本；坏证据截止与最后新样本时间独立，普通快流量不延长坏证据。相同策略共享恢复进度，票据绑定 runtime、策略代次、projection generation 和单在途 lease；过期、投影删除重建或重启不复活旧票。读取即时判断 15 分钟有效期，不产生新恢复机会、不刷新样本年龄。

runner 的完成消费、每秒快照刷新和每分钟清理独立运行。一个完成批次最多 4 个 worker，同账号串行，不同账号有界并发；跨实例由事务锁、claim lease 和事实唯一键保证幂等。清理每批最多 1000 条，在 2 秒上下文预算内连续处理，只删 48 小时外已处理事实，失败不撤回快照。

管理列表先取稳定排序的质量候选 ID 和必要字段，复用原 Go 质量评分/筛选函数，分页后加载完整关联。不同账号的统计窗口费用使用一条按账号及窗口边界的 SQL。底层 singleflight 只合并同时进行、授权身份及完整条件相同的读取，完成即移除；每个调用方独立取消和生成保护状态。完整响应生成后才比较 ETag，不加入固定 TTL 或提前 304。前端保留现有刷新间隔、后台暂停、详情行为、未变化行复用与失败时最后成功数据，用请求代次避免旧响应覆盖新筛选。

迁移 299 仅追加事实版本、pending 标记及定向查询索引；保留旧 SQL/profile/checksum，并由 trigger 兼容旧镜像写入。定向账号窗口 SQL 的事实子查询和最外层状态查询都必须过滤同一账号集合，不能用无关 LEFT JOIN 零行覆盖其他账号。发布必须另行验证真实 PostgreSQL 升级/重放、旧镜像兼容和签名 Gate。验证报告应区分算法差分、SQL mock、微基准、真实数据库局部入口及完整 API 混合负载，各自不能替代未执行层级的证据；数据库调用增加和复制分配开销也需记录。

冻结旧实现的缓存事件与联合调度 golden 分别由 `frozen_event_oracle_test.go`、`protection_joint_oracle_test.go` 维护，来源和固定时钟复现命令保存在各包 `testdata`。驻留、清理与时间相关 ETag 边界分别由 `session_residency_boundary_test.go`、`upstream_cache_guard_cleanup_test.go`、`account_protection_expiry_etag_test.go` 覆盖。更改 golden 必须先运行冻结旧源码取得期望，不能用待验证实现更新期望。

真实 PostgreSQL 跨进程回归入口为 repository 包的 `TestCacheGuardCrossProcessPostgres`，需 `cacheguardpg` build tag、明确独占的测试 DSN 和 `SUB2API_CACHE_GUARD_TEST_ISOLATED=1`，数据库名必须含 `test`。夹具启动两个独立进程，覆盖请求及完成事实幂等、同会话跨账号竞争，以及领取者退出后的活租约隔离和过期重领；最终要求有效样本只计一次。无 DSN 的跳过和同进程双 Engine 回归均不能替代该验证。仅允许在隔离合成库运行并清理自有资源。

## 长会话准入存储与漏采诊断

### 一致读取与独立采样

保护择优和发送准入分别使用一致读取视图：`CachedCandidatesReadView` 同时读取当前候选与会话，`CachedAdmissionReadView` 同时读取元信息、实际账号与会话。单次视图在同一发布读锁内取得评估时间、策略代次、设置与状态；等待刷新发布的读者在取得锁后读取时间，不能把正常发布误判为时钟回拨。显式传入的固定时间仍严格检查负年龄及 5 秒 / 30 秒边界，不通过夹紧时间掩盖真实回拨。会话冷加载完成后重取完整视图，不能拼接旧候选与新会话。策略设置和代次在同一发布锁内更新；发送前仍核对策略代次、当前账号/Key 和普通调度硬约束。

快照不可用、策略投影暂不可用或无法可靠读取旧会话时，普通调度选定的请求可在发送前同步提交 `CaptureOnly` admission。它独立冻结当前账号、Key、模型、实际协议与请求开始时的物理暖上下文，保留原请求幂等身份；不因页面没有缓存率而停止采集后续事实。首次请求及首个成功完成前已经发出的并发请求仍为冷请求，完成后的暖状态不得倒写开始分类。采样必须满足原有平台、文本业务、可靠逻辑会话及有效用量条件，不能由质量列的活动数推导暖样本。

`CaptureOnly` 保留首次会话身份与自然新会话序号，并抑制该会话后续补领试用；不增加试用计数、不启动恢复 cohort、不改变保护亲和、驻留或迁移进度。其完成事实可更新物理暖上下文、共享原始统计和满足原门槛的降级判断，但不推进恢复或低率迁移连续计数；初始策略投影和后台刷新同样不能借这些事实制造恢复。超过保护证据期限变为未知的原规则保持不变。此机制不回填历史请求，也不承诺采样率达到全部业务请求数。

联合调度的严格发送标记也用于 TTFT；只有当前分组有效缓存策略为 `protect` 时，才因缓存快照不可用要求普通重选。`observe` 或本组缓存停用但其他组仍采集时可独立 `CaptureOnly`，不能由缓存未知撤销合法 TTFT 选择；全部缓存策略停用时不启动缓存数据库操作。TTFT 真实票据的账号、Key、模型、租约和策略代次校验仍由发送边界执行，不因缓存停用而放宽。

新增 JSON 字段缺省时旧历史仍可读取；这不代表旧二进制可安全处理新 `CaptureOnly` 记录。旧完成 worker 忽略该标记会把纯采样当普通完成并更新亲和等保护解释，因此未来发布必须统一切换全部 admission/completion 写入者和消费者，禁止新旧二进制混写或混消费。本改动不新增 SQL 迁移或 release profile；本地验证不代表部署完成。

保护数据库阶段共用同一逻辑请求的累计 100ms 活跃操作预算，包含会话冷加载、试用规划、同步 admission 与 `CaptureOnly`；短于该值的调用方截止时间仍优先。数据库阶段结束立即释放阶段上下文，各阶段间的普通计算不消耗活跃数据库预算；并发阶段通过同一预算租约串行消费剩余额度。预算耗尽改用普通调度的原请求上下文，不能重置 100ms、扩大预算或发送后异步补录开始分类。采样准入或持久化失败继续安全放行业务，明确记录缺口。

### 进程诊断接口与对账边界

管理员可读取 `GET /api/v1/admin/accounts/:id/cache-guard-diagnostics`，响应使用 `Cache-Control: no-store`。接口按账号当前 Key 返回进程标识、runner 状态、有界采样计数及各关联分组的一致内存快照诊断；不冷加载会话、不推进试用或恢复、不额外重算数据库窗口。快照诊断区分策略代次不匹配、尚未核验、核验超期、采样失败和账号数据缺口；缺口是聚合状态，不能一概解释为未完成请求。诊断原因存在不等于 `available=false`，30 秒容忍窗口内仍可能可用但不新鲜。

计数固定为 `count_scope=process_account_window`，只覆盖当前进程、当前保留身份与计数代次，最多 4096 个身份并按 FIFO 淘汰；重启、淘汰及多实例会分割观察范围，`complete_history=false` 明确不代表完整历史。完成观察计数不是数据库去重后的事实数，不能直接与质量列近 1h 请求数相减计算漏采率。需要固定账号、Key 与时间范围，并分别核对业务完成、开始准入、冷/暖分类、用量已知状态、完成入队和处理确认。接口只暴露白名单元数据，不返回原始会话、请求正文、提示词或凭据；上线前的历史缺口无法由新增计数还原。

`BenchmarkAdmissionReadView` 固定单个驻留会话和一个实际账号，按总目录 100 / 1,000 / 10,000 个账号对照一致视图与此前元信息、账号、会话三次有界读取。复现命令为在 `backend` 运行 `GOTOOLCHAIN=go1.27.2 go test ./internal/upstreamcacheguard -run '^$' -bench '^BenchmarkAdmissionReadView$' -benchmem -benchtime=500ms -count=3`（PowerShell 先设置对应环境变量）。它只衡量内存读取和分配，不包含 SQL、并发刷新、调度或生产延迟；一致性与诊断可增加固定开销，不能将其描述为吞吐改善，亦不能使用全目录快照充当本轮旧基线。原始结果与一次性说明保存在 `.tmp`。

会话主体只保存首次身份、自然试用序号、路线和亲和状态；逐请求准入账本存入 `upstream_cache_guard_admissions`，主键为 `(group_id, session_key, admission_key)`。准入按主键检查幂等并写入本次记录，完成后定向标记完成；同路线未完成屏障和采样失败完成确认通过索引读取，账号级缺口检查只读取超容忍窗口的真实未处理完成事实，不再读取整个未完成 admission 历史。请求不再反复反序列化和写回长期会话的完整 admission 历史。已完成记录继续按墙钟的既有 48 小时期限分批清理，48 小时内保持幂等，超过期限不承诺旧实现偶然更久的幂等保留；未完成记录始终保留，不以 TTL 删除或提前置为已完成，仍影响判定的路线不因账本清理删除。

未完成 admission 与完成事实缺口的区分仅调整读取与快照发布逻辑，不新增 SQL 迁移或 release profile。现有 5 秒新鲜 / 30 秒可用快照、默认 15 分钟保护证据期限、温热续聊、试用、迁移和恢复条件保持原合同。

`split_admission_test.go` 的 `TestSplitAdmissionOldUnfinishedSurvivesRestartWithoutGapAndCompletionAcknowledgesFailure`、`TestSplitAdmissionQueuedCompletionSurvivesRestartAndRecoversAfterConsumption` 与 `TestSplitAdmissionUnfinishedAloneCannotRestoreProtectedAccount` 分别覆盖旧账本重启、完成积压恢复和不伪造健康；`TestSplitAdmissionUnfinishedAttemptRemainsLowStreakBarrier` 保留迁移屏障回归。`snapshot_availability_test.go` 的 `TestPendingFactStrictBoundaryAndRefreshFailureNeverRenewIncompleteSnapshot` 核对严格边界与失败不续期；`upstream_cache_guard_bootstrap_test.go` 的 `TestUpstreamCacheGuardUnfinishedAdmissionDoesNotBlockSendAdmission` 和 `TestUpstreamCacheGuardPendingFactBlocksOnlyItsAccount` 验证发送准入与账号隔离。repository 的 `TestCacheGuardAdmissionHealthPostgres` 使用隔离 PostgreSQL 双连接池，核对跨实例可见性、有效 lease、Key 来源、聚合去重及 cutoff 边界；SQL mock 另覆盖流读取和完成确认查询失败。这些测试不代表生产环境修复或部署完成。

拆分不改变有效样本条件：成功、允许采样、请求开始时已温热、原始缓存用量已知。温热分类在发送前冻结，首次请求及首个成功完成前并发发出的请求仍为冷请求；不能用请求完成后的状态倒改分类。自然试用配额、cohort、恢复和迁移条件、账号→会话→分组配额锁序保持不变。准入仍在发送前同步、原子、幂等提交，保护数据库共用 100ms 请求预算；失败按现有规则放行或普通重选，不能通过扩大预算、异步补录或放宽温热标准提高样本数。

`upstream_cache_guard_sampling` 按 `(group_id, account_id, upstream_key_id)` 记录有界进程窗口计数，最多保留 4096 个身份并以 FIFO 淘汰；日志标明 `count_scope=process_account_window`。完成相关计数是代码观察次数，并非数据库去重后的事实数。预算诊断保留操作名、总耗时、操作间隔和固定阶段耗时；不得输出原始 session、正文或凭据。稀疏日志及进程窗口计数只能辅助定位，不能用来宣称全部缺失请求均由某一锁或 JSON 开销造成。对账需固定相同账号、Key、起止边界，分别核对业务成功、准入、持久事实、冷请求、失败与有效样本。

迁移 301 原子展开旧 JSON admission 账本，保留全部未完成和已完成记录；轻量主体删除 `admissions` 并推进版本，保留原业务 `updated_at`。Key 只取原 admission 的明确值或同一冻结路线的来源；无可信来源保留 0，不猜测当前 Key。迁移保留 299 的事实版本和 pending trigger 等对象，但新代码从独立账本读取准入状态。旧二进制不能正确写入新结构，因此 274 只允许 `downtime`：停止旧写者后迁移，回退必须恢复同一恢复点的数据库与旧镜像（`coordinated_restore`），不得把旧镜像继续写入视作兼容。既有旧镜像、恢复和签名 Gate 验证保持 fail-closed，不能用本地测试替代。
