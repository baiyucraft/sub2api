# 用户资金汇总与开票标注

管理员在用户管理的“用户资金与权益变动记录”中查看类型汇总和“已开票”摘要。开票金额使用与站内余额相同的显示单位，登记的是管理员业务标注；不引入币种、汇率、税额或外部税务流程。

## 类型汇总

`GET /api/v1/admin/users/:id/balance-history` 保留既有分页、总充值和累计领奖字段，追加 `filtered_amount`、`filtered_quantity`。`total` 是当前类型全部记录的条数；汇总在分页之前完成，因此翻页不会改变条数和合计。

金额类型按记录正负金额净合计；并发类型合计并发变动数量。订阅和混合类型只显示条数，不把金额、并发和订阅时长相加。没有记录的适用汇总为零，不适用的汇总为 `null`。总充值和累计领奖维持原来独立的历史口径，不随类型筛选改变。

## 开票登记

“已开票”摘要位于用户概要中，不随资金记录类型切换；“登记开票”及摘要入口打开该用户的开票明细。金额和日期必填，发票号码、备注可选。一个标注可覆盖多笔充值，也可补录历史开票，不强制绑定某笔资金记录。

管理员接口：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v1/admin/users/:id/invoices` | 分页列出有效和已作废标注，返回跨全部开票页的 `total_invoiced` |
| POST | `/api/v1/admin/users/:id/invoices` | 创建标注，`operation_id` 用于重复提交保护 |
| PUT | `/api/v1/admin/users/:id/invoices/:invoice_id` | 更正有效标注金额、日期、号码和备注 |
| POST | `/api/v1/admin/users/:id/invoices/:invoice_id/void` | 填写原因后作废，保留记录和审计 |

累计已开票只计算 `active` 标注。作废后金额从累计中移除，已作废记录不能更正。操作人来自管理员鉴权上下文，禁止客户端指定；记录 ID 必须属于路径中的用户，跨用户和未知记录拒绝。

创建的幂等范围是 `user_id + created_by + operation_id`，相同键和相同请求返回原标注，相同键不同请求拒绝。金额必须大于零、小于 `1e12`、最多 8 位小数；日期采用合法 `YYYY-MM-DD`，发票号码最多 100 字符、备注最多 1000 字符，作废原因必填且最多 500 字符。

更正请求携带打开表单时记录的 `expected_updated_at`。锁定记录后，若内容已与请求一致，则作为成功重试返回；否则必须匹配原更新时间，不匹配返回 `409 / USER_INVOICE_STALE`，界面要求重新加载后再编辑。每次实际更正或作废的更新时间至少递增一微秒，避免同一时刻的版本重用。这样，提交成功但响应丢失后的旧请求不会覆盖其他管理员随后完成的更正。

## 存储与审计

`user_invoice_annotations` 保存用户 ID、金额、开票日期、号码、备注、状态、操作人时间和作废信息；`user_invoice_annotation_events` 保存创建、更正和作废的 before/after 快照及操作人时间。标注和审计写入在同一事务提交，失败不允许出现只更新金额而缺少审计的状态。

两张表不引用 `users` 外键，避免用户删除时级联丢失历史登记和审计身份；事件对标注使用 `ON DELETE RESTRICT`。作废状态要求原因非空、作废人明确非空且大于零、作废时间非空，不能依赖 PostgreSQL 对 `CHECK UNKNOWN` 的允许行为。

开票操作不写入用户余额、充值、退款、消费、奖励、联盟或权益账本；不改变开票用户的消费能力。它也不限制登记金额必须小于历史充值金额，因为历史补录和线下业务标注并不绑定站内资金记录。
