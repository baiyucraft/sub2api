# 可选图片工具与分组策略

此合同由 fork 扩展 `openai-image-permission-routing` 维护。Codex 直连与 Magpie 转发采用相同的结构化分类，不根据用户自然语言猜测图片生成意图。

## 分组清理与权限

`groups.strip_optional_image_tools` 是默认 `false` 的布尔配置，创建、查询、复制及认证/调度快照同步携带；更新省略字段保持原值，显式 `false` 关闭。更新配置须触发认证缓存失效，数据库直写也经 outbox 失效。

| 允许生图 | 移除可选图片工具 | 可选声明 | 明确图片请求 |
| --- | --- | --- | --- |
| 否 | 任意 | 自动清理 | 按既有权限拒绝 |
| 是 | 开启 | 清理，禁止 bridge 自动补入 | 继续图片权限与能力校验 |
| 是 | 关闭 | 兼容既有账号声明策略 | 保持图片流程 |

清理在分组图片权限、生图并发和账号选择之前生效。清理后的普通请求不占图片并发槽。分组清理优先于 hosted bridge 的账号、渠道及全局自动注入配置；既有账号手动声明策略独立保留。

## 图片意图与历史

图片端点、图片模型、明确图片工具选择及可确认的图片调用历史要求图片能力。统一识别 native、namespace 和 function 图片工具；native 的省略选择、`auto` 和 `none` 属于可选声明。`required` 只有在可选工具全部属于图片工具时才构成强制生图；混合工具不能直接升级。

调用历史按调用 ID 配对工具名称。普通 shell、搜索、读文件及其结果不证明生图；无法确认来源的输出为 unknown。单独的 `previous_response_id` 不证明生图，也不推导权限；保留全部历史、结果、续接 ID、ownership、账号粘性和续链校验。不新增跨请求调用历史缓存，图片输入也不等于图片生成。

清理仅移除可选图片声明，覆盖顶层 `tools` 与 Lite `additional_tools`；明确图片选择和真实图片历史不能被该路径降级。`allowed_tools` 同步移除图片引用，保留其余限制；续接请求没有重复工具目录时，同样清理限制中的可选图片引用。可选限制清空时选择 `none`，不得改成无限制调用；无图片引用的原有空限制保持不变。

## 转发与错误

入站分类是 HTTP、WS 首包与每次物理发送的统一依据。每个候选从原始请求独立派生，失败切换不污染下一账号的工具列表。WS 覆盖 session 继承、`session.update`、多轮、重连和恢复；需要清空继承工具时必须显式发送空列表，不能因省略字段恢复图片工具。

compact 保持既有的逐账号模型映射合同：图片模型映射到文本模型时按该次实际发送模型校验，明确图片工具选择和真实图片历史仍要求图片能力。

仅图片能力筛选或明确图片权限失败导致候选耗尽时返回 `503 image_generation_unavailable`。出现模型路由、网络或其他上游错误时沿用原有失败选择和状态映射，不能用图片错误覆盖普通故障。固定上游图片权限 403 仍只冷却图片能力，不惩罚文本或全账号健康。权限快照刷新等元数据失败保留普通上游失败归因，不能报告图片能力耗尽。WS 每个成功 turn 结束后重置失败归因 trace，避免前一轮错误污染后续请求。

入站和失败出口只记录分类标志、清理原因与失败类别等白名单元数据，不保存提示词、工具参数、完整请求、续接 ID 或凭据。历史错误计数仅是调查基线，没有原请求体时不能报告确定误判数或修复率。
