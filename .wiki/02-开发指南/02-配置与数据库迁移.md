# 配置与数据库迁移

配置结构由 `backend/internal/config/config.go` 定义；新增字段需同步默认值、校验、样例和部署文档，敏感值只受控注入。

`migrations_runner.go` 维护 `schema_migrations(filename, checksum, applied_at)`，使用 advisory lock；`_notx.sql` 表示非事务迁移。`migration_plan.go` 对 SQL 排序、计算 catalog SHA-256、比较数据库记录，发现 checksum conflict 或 unknown 时拒绝执行。

推荐：新增编号 SQL -> 生成只读 migration plan -> 核对 pending/existing/conflicts/unknown -> 仅执行已核验 plan。失败后先 reconcile，不盲目重试。生产回滚依赖显式 SQL 或备份恢复。

Fork 专属迁移、profile、checksum 和历史证据的长期合同见[分叉扩展与兼容性](../03-模块指南/05-分叉扩展与兼容性.md)。新增或改动与 `upstream/main` 不同的 migration 时，必须同时更新 audit catalog 与 Wiki；历史 profile 不回写，不能通过删除 migration 记录或重建数据库消除冲突。
